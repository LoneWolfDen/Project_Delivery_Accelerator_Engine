## 0. Summary

The target is a **browser-only, no-build Progressive Web App**: plain HTML, CSS and JavaScript ES modules, with all user data kept in the browser's IndexedDB on the user's own device, and a user-controlled backup file.

- No Python server at runtime, no Docker, no database server, no framework, no transpiler.
- The app is a set of static files. It reaches the user in one of two ways:
  1. **Hosted (primary):** the user opens a URL in Edge or Chrome and clicks **Install**. Only the app's code is downloaded from the host; no user data is ever sent there.
  2. **Local (fallback):** the user unzips a release and double-clicks a start file, which serves the same static files on `http://127.0.0.1:8765`.
- Works fully without AI. AI is optional and limited to **OpenRouter**, off by default, with a preview of exactly what will be sent before every request.
- Microsoft 365 Copilot is supported **without any API**: the app prepares a copy-ready package, the user takes it to Copilot, and pastes the reply back, where it's stored as a **Draft**.
- The existing Python application is **retired** after the new app reaches the agreed feature scope. Its domain logic (extraction patterns, persona definitions, review heuristics) is ported to JavaScript behind characterization tests. Its two UIs are not carried over (OD-2).

## 1. Build model decision: A. Human-readable no-build PWA

The prompt requires an explicit choice between **A** (no-build) and **B** (reproducible build). **A is chosen.**

| Evidence | Source | Bearing on the choice |
|---|---|---|
| No healthy build system exists to preserve. There's no `package.json`, bundler, transpiler or lockfile; the front end is already unbuilt vanilla JS. | `DEPENDENCY_BUILD_REGISTER.md` §1, §3 | Nothing to reuse that would justify B |
| The only build-like systems (Python packaging, Docker, CI) are all broken | D-1, D-2, D-7, D-8 | Adding a new build chain adds a failure surface the owner can't maintain |
| No minified or generated application code; the browser runs readable source | `MINIFIED_AND_GENERATED_CODE_REGISTER.md` §1 | A keeps that property by construction |
| Owner isn't a software engineer; users are non-technical | OD-1, §14 context | Every extra toolchain step is a support burden |
| Repeated page-load and SyntaxError regressions (#114–#118) came from editing huge inline-script HTML, not from the absence of a build | assessment §12 | Fix by modular ES files plus browser tests, not by a bundler |
| The charter says to prefer the smallest architecture that works, and not to add a framework to look modern | charter §2, §3 | A is the smallest |
| Modern Edge, Chrome and Safari all support native ES modules, IndexedDB, service workers, `crypto.subtle`, `DecompressionStream` and `<dialog>` | Platform | No transpilation needed for the target browsers (§27) |

**Development tooling isn't a build.** Tests and checks use Node.js only as a dev tool (`node --test`, Playwright) declared in a dev-only `package.json` with a committed `package-lock.json`. Nothing in `node_modules` is ever served. The served files are byte-for-byte the files in `app/`. One small file, `app/precache-manifest.js`, is **generated** by a checked-in script (`tools/precache.mjs`), and CI fails if it's stale (charter §2, "generated code must have a checked-in generator").

## 3. Runtime architecture

```
┌──────────────────────────── User's browser (Edge / Chrome / Safari) ───────────────────────────┐
│  UI (views, components) ──► store (in-memory state, pub/sub) ──► services (pure domain modules)│
│        ▲                                                         │                             │
│        │ events                                                  ▼                             │
│  diagnostics log ◄──────────────────────────── storage repos ──► IndexedDB "pdae" (per origin)  │
│                                                                   ▲                             │
│  service worker: app-shell cache only (never user data)           │ backup / restore (file)     │
└──────────────────────────────────────┬──────────────────────────────┬────────────────────────┘
                                       │ code download only            │ only on explicit user action
                          GitHub Pages / 127.0.0.1           https://openrouter.ai (optional, consented)
```

- **No back end.** No server-side API, so the legacy CORS, CSRF, path-traversal and unauthenticated-admin classes (security B-1, B-2, H-1–H-4) don't exist in the target.
- **One origin, one data store.** IndexedDB is scoped to the origin (scheme, host and port). Hosted and local copies therefore hold **separate** data; moving between them is done with backup and restore (`DATA_AND_STORAGE_ARCHITECTURE.md` §8).
- **Single writer.** All writes go through `storage/` and are serialised with the Web Locks API (`navigator.locks.request("pdae-write", …)`), so two open tabs can't interleave writes. A `BroadcastChannel("pdae")` tells other tabs to refresh.

## 4. Module boundaries

| Module | Responsibility | May depend on | Must not |
|---|---|---|---|
| `core/` | IDs, time, SHA-256, result type, label constants | nothing | touch DOM, storage or network |
| `domain/` | Data shapes, validation, invariants | `core` | touch DOM, storage or network |
| `storage/` | IndexedDB access, migrations, backup and restore, quarantine | `core`, `domain` | touch DOM (except via returned results) or network |
| `import/` | Turn user-chosen files into `Source` + `Chunk` records with provenance | `core`, `domain` | persist directly (returns records); fetch network |
| `extract/` | Deterministic extraction of risks, assumptions, dependencies, constraints, actions and scope, each with citations | `core`, `domain` | call AI |
| `review/` | Persona reviews (deterministic), honest labelling | `core`, `domain`, `extract`, `search` | call AI directly (goes through `ai/`) |
| `search/` | Chunk index, query, evidence selection | `core`, `domain` | generate prose |
| `ai/` | Provider interface; `none` and `openrouter`; consent; response validation | `core`, `domain` | be called without a `consent.js` token |
| `connectors/` | Where files come from and go to (V1/V2 now, V3 later) | `core` | read files the user didn't choose |
| `exports/` | Markdown, HTML, JSON, manifests, Copilot package, ZIP | `core`, `domain` | upload anything |
| `ui/` | Rendering and interaction | all of the above via `store` | use `innerHTML`, `eval`, inline handlers |
| `diagnostics/` | Event log and report | `core` | log document content, prompts or keys |

`tools/check-forbidden-apis.mjs` enforces the "must not" column (e.g. `fetch(` allowed only in `ai/openrouter.js` and `sw.js`; `innerHTML` nowhere).

## 5. State management

- **Persisted state** is in IndexedDB, and only `storage/repos/*` reads or writes it.
- **Session state** lives in `ui/store.js`: a single plain object (current project, view, filters, in-flight jobs) with `subscribe(fn)` / `update(patch)`. No framework.
- **The OpenRouter key and other secrets** are held in memory only, in `ai/openrouter.js` module scope, and cleared on tab close (§21).
- **UI preferences** (last view, screen-share mode, theme) may use `localStorage`, wrapped in `try/catch`. Never content, never secrets.
- Views re-render from the store; long jobs (parsing, extraction, indexing) report progress to the store and run in chunks with `await` yields so the page stays responsive. A Web Worker can be introduced later for PDF only if measurement shows a need.

## 6–8. Local storage, backup and restore, schema versioning

Specified in full in **`DATA_AND_STORAGE_ARCHITECTURE.md`**. In summary:

- IndexedDB database `pdae`, schema version = IndexedDB version number, with ordered, atomic migrations.
- Persistent storage is requested (`navigator.storage.persist()`), and usage is shown (`navigator.storage.estimate()`).
- Backup is a single `.pdae-backup.json` file (manifest, per-record SHA-256, whole-file checksum), user-initiated download.
- Restore previews first, never overwrites silently, and offers a backup of the current data before replacing.
- Corrupt records go to quarantine, never deleted. Delete goes to Trash first, and permanent delete needs typed confirmation.

## 9–10. File import and provenance

- V1 accepts files only through `<input type="file" multiple>` and drag-and-drop.
- Every file is parsed into a **preview** (text, sections, rows and detected items). The user chooses **Keep** or **Discard**; nothing is stored before Keep.
- Supported in the first release: `.txt .md .csv .eml .json .docx`. `.pdf` comes in a later slice, via a vendored `pdf.js` (ADR-009).
- `.docx` is read without a third-party library: ZIP central directory plus `DecompressionStream("deflate-raw")`, then `DOMParser` over `word/document.xml`.
- Every `Source` carries a provenance record:

```
provenance = {
  sourceSystem: "local-file" | "synced-folder" | "graph" | "pasted-text" | "external-draft",
  fileName, relativePath?,            // relativePath only from a user-selected folder (V2)
  sha256, sizeBytes, mimeType,
  importedAt, lastModified,           // File.lastModified → "as-of" unless the user overrides
  asOfDate, asOfSource: "file-modified" | "user-entered",
  parser: { name: "docx", version: "1.0.0" }, appVersion
}
```

- Every `Chunk` carries a **locator**: `{page?, sheet?, row?, paragraph?, heading?, messageId?, charStart, charEnd}`. Every extracted item, review finding and answer cites `chunkId` plus the quoted span, so citations resolve to exact text.
- Re-importing a file with the same `sha256` in the same project is detected and offered as "already imported", never silently duplicated or overwritten. This fixes the stem-collision overwrite (security M-6).

|---|---|---|

## 18. Service worker

- **Scope:** the app root. **Strategy:** precache the app shell (every file in `precache-manifest.js`), serve cache-first, and never cache anything from other origins. It never intercepts requests to `openrouter.ai`, and never stores user data.
- **Versioning:** the cache name is `pdae-shell-<APP_VERSION>-<manifestHash>`. A new release installs into a new cache, and the old one is deleted only on `activate`.
- **Update flow:**
  1. A new worker installs and waits (no automatic `skipWaiting`).
  2. The UI shows: "Update available (v1.4.0). Download a backup first (recommended) · Update now · Later".
  3. Update now posts `SKIP_WAITING`, and the page reloads once on `controllerchange`.
- **Schema guard:** if a release raises `SCHEMA_VERSION`, the prompt states it and offers a backup first (`DATA_AND_STORAGE_ARCHITECTURE.md` §7).
- **Kill-switch (charter §10):** `reset.html` is reachable even if the main shell is broken (it's precached separately and also loaded network-first). It:
  1. unregisters all service workers for the origin;
  2. deletes `pdae-shell-*` caches;
  3. **does not touch IndexedDB**;
  4. reloads.

  A remote kill-switch is also checked on each start: `sw.js` fetches `kill-switch.json` network-only, with a 3-second timeout, ignoring failure. If it contains `{"disable": true, "below": "<version>"}`, the worker unregisters itself.
- **Tests before release:** offline start, update prompt, kill-switch, and a stale shell with a newer schema (§24).

## 19. Manifest and installability

`manifest.webmanifest`:

- `name`, `short_name`, `id: "./"`, `start_url: "./"`, `scope: "./"`, `display: "standalone"`
- `background_color` and `theme_color` from tokens
- icons 192 and 512 (`any` and `maskable`)
- `description`, `categories: ["productivity"]`
- **no** `share_target` or `file_handlers` in V1. They're candidates for V2: `file_handlers` would let users open `.pdae-backup.json` or documents straight into the installed app in Chromium.

Installability in managed Edge or Chrome depends on tenant policy (the `WebAppInstallForceList` / install-blocking policies). The app must work fully in a normal browser tab too, and installation is a convenience. This is recorded as an external dependency.

## 20. Cache lifecycle

| Event | Behaviour |
|---|---|
| First visit | SW installs and precaches the shell; the app works offline from then on |
| Normal start | Shell from cache; `sw.js` itself is revalidated by the browser (byte check) |
| New release published | New SW installs in the background → update prompt (§18) |
| User clicks "Later" | Old version keeps running; the prompt reappears next start |
| Broken release | Publish `kill-switch.json` and/or tell the user to open `reset.html`; then republish the previous version |
| Cache eviction by the browser | The shell is re-downloaded on the next online start; IndexedDB has separate persistence (§6) |
| Local fallback (`127.0.0.1:8765`) | Same SW logic; the release zip is the version; the port is fixed so the origin (and data) stays stable |

## 21. Configuration

- All settings live in the IndexedDB `settings` store, editable in **Settings**, and included in backups:
  - default persona
  - screen-share mode
  - AI enabled/disabled
  - OpenRouter model ID
  - payload size limit
  - Copilot package size limit
  - trash retention days
  - date format
- **Secrets aren't stored.** The OpenRouter key is entered per session and kept in memory only (charter §4: "no stored API keys in localStorage"). The UI explains this in one line.
- Build-time constants are in `app/version.js` only. No environment variables, because there's no server.

## 22. Logging and diagnostics

- `diagnostics/log.js` keeps a ring buffer of the last 500 events in memory, mirrored to the IndexedDB `diagnostics` store: `{time, level, code, module, message, refs: {projectId?, sourceId?}}`.
- **Never logged:** document text, chunk text, prompts, AI responses, file contents, API keys.
- File names are logged only as `sourceId`.
- Every storage failure, quota error, migration failure, parse failure or AI error produces a **visible banner** with a stable code (e.g. `STO-QUOTA`, `MIG-0003-FAIL`, `IMP-DOCX-ZIP`) and a "What can I do?" link to plain-language help.
- **Diagnostics view:** storage usage, persistence status, schema and app version, SW version, quarantine count, recent events, and **Download diagnostic report** (JSON, content-free).

## 23. Security controls

| Control | Implementation |
|---|---|
| Content Security Policy | `<meta http-equiv="Content-Security-Policy">` (GitHub Pages can't set headers): `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self' https://openrouter.ai; worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; require-trusted-types-for 'script'; trusted-types pdae-script-url`. Meta CSP can't set `frame-ancestors`, which is a known limitation. |

Under Trusted Types, Chromium throws if any HTML sink receives a string. The single allowed policy `pdae-script-url` (in `main.js`) returns a `TrustedScriptURL` only for a fixed allow-list (`./sw.js`, and later `./vendor/pdfjs/pdf.worker.mjs`); it's required because `navigator.serviceWorker.register()` and `new Worker()` are Trusted Types sinks. | Untrusted document content | Rendered as text. Markdown and email are displayed through a safe subset renderer that creates DOM nodes. Links in documents are shown as text, not made clickable, in V1. |
| External transmission | Only `ai/openrouter.js` may call `fetch` to a non-self origin, and only with a consent token created by the user's click on the payload preview (`COPILOT_AND_CHAT_ARCHITECTURE.md` §4) |
| Secrets | Session-memory only; never in IndexedDB, `localStorage`, logs, backups or exports |
| Destructive actions | Trash first; typed confirmation for permanent delete, restore-replace and reset; backup offered first |
| Supply chain | No runtime dependencies at first; any vendor file is pinned by SHA-256 in `VENDOR_MANIFEST.json` and verified in CI |
| Hosting | Static only; HTTPS (GitHub Pages) or `127.0.0.1` (fallback launcher binds loopback only) |
| Source maps / debug | None exist; none served |

## 25. Release packaging

1. Bump `app/version.js` (semantic versioning); `SCHEMA_VERSION` only when migrations change.
2. `node tools/precache.mjs` regenerates `app/precache-manifest.js` (CI verifies).
3. Tag `vX.Y.Z` on `main`. CI then:
   - runs all gates;
   - publishes `app/` to GitHub Pages;
   - attaches `pdae-vX.Y.Z.zip` (contents of `app/` + `launch/` + `RELEASE_NOTES.md` + SHA-256 list) to the GitHub release.
4. Keep the previous two release zips available. They're the rollback route for local users, and the source for re-publishing Pages.
5. `RELEASE_NOTES.md` states: changes, schema change yes/no, data-boundary changes, known limitations.

Until the repository is public, GitHub Pages may be unavailable on the current plan (an external dependency). In that period the release zip and local launcher are the delivery route.

## 26. Start-up on Windows and macOS

| Route | Windows | macOS |
|---|---|---|
| Hosted (primary) | Open the URL in Edge → address-bar **Install** (or ⋯ → Apps → Install) → icon in the Start menu; opens offline thereafter | Chrome or Edge: same; Safari 17+: File → Add to Dock |
| Local fallback | Unzip the release → double-click `start-windows.bat` → runs `python -m http.server 8765 --bind 127.0.0.1 --directory app` and opens `http://127.0.0.1:8765/` | Unzip → double-click `start-macos.command` (same command, `python3`) |
| Stopping | Close the browser window; close the console window for the local route | Same |

- **Fallback prerequisites:** Python 3 present (OD-1). Corporate policy may block `.bat` or `.command` files, or SmartScreen/Gatekeeper may warn; `README-START.txt` explains this in plain language.
- **Port 8765 is fixed** because changing it changes the origin and therefore hides existing data.
- Opening `index.html` directly from disk (`file://`) **isn't supported**: ES modules and service workers don't work there. The page shows a plain-language message if that happens.

## 28. Accessibility

- Target WCAG 2.2 AA.
- Semantic HTML, with `<button>` for every action (no clickable `div`s, which fixes the current pattern). Labels on every input. One `<h1>` per view and a logical heading order.
- Visible focus (`:focus-visible`) and a skip link. `<dialog>` for modals, with focus return. `aria-live="polite"` region for progress and results.
- Fully keyboard-operable journeys, tested in CI (§24).
- Colour tokens checked for 4.5:1 text contrast. Never colour alone for labels: Fact, Inference, etc. carry text and an icon.
- `prefers-reduced-motion` turns off transitions; `prefers-color-scheme` gives light and dark themes; layout holds at 200 % zoom and 320 px width.
- Plain-language copy throughout, aimed at non-technical users (OD-1).

## 29. Screen-sharing readability

A **Presentation mode** toggle in the header (persisted as a UI preference):

- base font 125 %, line length capped, high-contrast theme, larger hit targets;
- hides the OpenRouter key field, diagnostic IDs and file paths, and collapses side panels;
- an optional **Hide names** switch replaces project and file names with neutral labels ("Project A", "Source 3") for demos;
- notifications stay on screen longer (no auto-dismiss under 8 s).

## 30. Migration from the current implementation
